# patch-reach - PERCEPTUAL environment. All of the perceptual analysis.
#
# Everything that scores how VISIBLE a patch is rather than how much damage it
# does: scripts/lpips_eval.py (LPIPS, DISTS, ST-LPIPS, LPIPS+, AHIQ, TopIQ-FR,
# PieAPP, SSIM/MS-SSIM/FSIM, ColorVideoVDP, and the no-reference NIQE /
# BRISQUE / CLIP-IQA / MUSIQ), scripts/score_reference.py and the panels built
# from their CSVs. On the cluster the env is called `lpips_eval`, which
# undersells it: LPIPS is only the primary metric, not the scope.
#
# SEPARATE FROM THE MAIN ENV ON PURPOSE, NOT BY ACCIDENT. The main env is
# pinned to torch 1.11 + mmcv 1.x + mmseg 0.x (see requirements-main.txt) and
# none of the metric packages install cleanly into it - pyiqa and cvvdp want a
# modern torch, and lpips' own weights load through a torchvision that mmcv
# 1.x will not tolerate. The scripts are written so that this is safe: they
# import only the model-free half of patchreach (patch/spec.py, patch/csf.py,
# data/cityscapes.py - torch + torchvision + numpy), rebuild the clean and
# patched frames from what the attack scripts already saved, and score the
# pair. No segmentor is ever constructed here, so no mmseg is needed.
#
#   conda env create -f envs/perceptual.yml
#   conda activate lpips_eval
#   pip install -r envs/requirements-perceptual.txt
#   pip install -e . --no-deps          # patchreach itself; deps are above
#
# CPU IS ENOUGH. LPIPS over a few hundred crops takes minutes; only the
# transformer-based metrics (AHIQ, TopIQ-FR, MUSIQ) really want the GPU, and a
# metric that runs out of memory on a full 1024x2048 frame is dropped with a
# message while the rest of the evaluation continues.

# cu118 to match `module load cuda/11.8` on the cluster; the wheels bundle
# their own CUDA runtime, so the module is not strictly required.
